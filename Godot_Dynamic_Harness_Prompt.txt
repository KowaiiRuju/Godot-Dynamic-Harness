### Phase 1: Deep Project Reconnaissance (Gather Context Slowly)
Do NOT rush into scaffolding. First, inspect the repository to understand what game is being built:
1. **Engine & Window Config**: Read `project.godot`:
   - Identify engine version, main scene (`application/run/main_scene`), and renderer (Forward+, Mobile, or Compatibility).
   - Check viewport resolution (`viewport_width`, `viewport_height`), stretch mode, and orientation.
   - List registered Autoloads / singletons.
2. **Dimension & Node Inspection**:
   - Check whether the game is **2D** (uses `Node2D`, `CharacterBody2D`, `TileMapLayer`, `CanvasItem`) or **3D** (`Node3D`, `CharacterBody3D`, `GridMap`, meshes).
3. **Genre & Core Mechanics Detection**:
   - Scan directory names, scripts, and scene hierarchies.
   - Look for systems: RPG elements (inventory, stats, dialogue, quests, equipment), Combat (hitboxes, health, state machines), Navigation (AStar, NavigationAgent), Multiplayer (ENet, RPCs), or Mobile features (touch, virtual joysticks).
4. **Summary**: Output a concise 4-bullet assessment of the game's genre, dimension, target platforms, and existing core architecture before continuing.

### Phase 3: Project Rules & The 8-Step Dynamic Harness Workflow
Deploy `AGENTS.md`, `.agents/rules/godot-harness.md`, and `.agents/workflows/godot-harness.md` enforcing:

1. **The 8-Step Dynamic Harness Workflow**:
   - **Step 0: Pre-Flight Router & Task Plan**: Run `python game.py route-prompt --prompt "<task>" --json` or `python game.py plan-task "<task>" --json`.
   - **Step 1: Skill Pre-Flight & Graph Query**: Call `read_file` on `matched_skill_paths`. Query `graphify query` or `python game.py scene-outline`.
   - **Step 2: Change Classification & File Leases**: Declare Minor vs Major. Acquire advisory leases via `python tools/agent_lock.py acquire` when `multi_agent: true`.
   - **Step 3: Scene-First Implementation**: Build UI and actor trees in `.tscn`. Expose tunables via `@export`.
   - **Step 4: Proportionate Verification**: Minor changes run targeted syntax and test suites. Major changes run full test and capture sweeps.
   - **Step 5: Visual Verification**: Render offscreen snapshots with `python game.py capture --scene <scene>`.
   - **Step 6: Write-Off Journaling**: Release leases and commit SHA-256 hashes via `python tools/agent_lock.py write-off`.
   - **Step 7: Context & Graph Refresh**: Run `python game.py context --refresh` and `graphify update .`.

2. **Scene-First / Editor-First UI Construction**:
   - The `.tscn` file is the ground truth. Always read `.tscn` before editing `.gd`.
   - NEVER construct UI in code with `Control.new()`, `Button.new()`, `Label.new()`, etc.
   - NEVER add or override styles in GDScript via `add_theme_*_override()`.
   - All HUD elements, dialogue boxes, menus, cards, and windows must be visually assembled in the Godot Editor. GDScript's only role in UI is binding data and reacting to signals.

3. **Inspector-Editable Nodes & Attributes**:
   - Expose tunable gameplay values via `@export`. Never bury constants in private script variables.
   - Top-down 2D entities align pivot with ground contact point and containers set `y_sort_enabled = true`.

4. **Multi-Agent Coordination & Advisory File Locks**:
   - Deploy `tools/agent_lock.py` and `tools/skill_router.py` to coordinate file leases and multi-agent write-off journals.

### Phase 4: Headless Verification Harness & The 15 `game.py` Commands

Scaffold the unified Python CLI runner (`game.py`) at the project root and helper utilities in `core/tools/`:

1. **`core/tools/scene_runner.gd`** (`extends SceneTree`):
   - Offscreen renderer for ANY game scene.
   - Uses an isolated APPDATA profile (`<project>_godot_qa_profile`) with `--rendering-method gl_compatibility --audio-driver Dummy` so visual captures never conflict with an open Godot Editor.
   - Dumps `scene_manifest.json` recording Control node bounding boxes and font sizes to detect clipping.

2. **`game.py` (The 15 Unified CLI Subcommands)**:
   - **`info`**: Displays engine version, renderer, viewport dimensions, and discovered tests.
   - **`route-prompt`**: 3-layer prompt router with dynamic skill matching and audit logging.
   - **`plan-task`**: Single-command routing + actionable task plan generation.
   - **`scene-outline`**: Fast scene hierarchy & Control node layout inspection without raw `.tscn` dumps.
   - **`capture`**: Offscreen viewport snapshot rendering to PNG with isolated APPDATA QA profile.
   - **`baseline`**: Golden visual screenshot regression testing and pixel diff comparison.
   - **`test`**: Headless GDScript unit and integration test runner for `tests/test_*.gd`.
   - **`validate`**: Static scene integrity, broken `ExtResource` paths, and procedural UI anti-pattern checks.
   - **`assets`**: Asset database, texture atlas scan, and orphan detection.
   - **`audit`**: Scene layout, bounding boxes, clipping, and font size inspection via `scene_manifest.json`.
   - **`saves`**: Inspect, validate, or wipe persistent save state files in `user://`.
   - **`syntax`**: Scan code for Godot 3.x vs 4.x syntax deprecations, or record newly learned patterns.
   - **`graph`**: AST-driven knowledge graph queries and dependency traversal via Graphify.
   - **`context`**: Generate or refresh persistent project context markdown and architecture summaries.
   - **`clean`**: Remove orphaned temp files, debug screenshots, and stale QA caches.

3. **`tests/test_smoke.gd`** (`extends SceneTree`):
   - Smoke test script verifying key scenes instantiate and advance 2 frames without errors.
