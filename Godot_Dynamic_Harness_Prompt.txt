### Phase 3: Project Rules (`AGENTS.md`)
Create a production `AGENTS.md` at the project root tailored to this game:
1. **Scene-First / Editor-First UI Construction**:
   - The `.tscn` file is the ground truth. Always read `.tscn` before editing `.gd`.
   - NEVER construct UI in code with `Control.new()`, `Button.new()`, `Label.new()`, etc.
   - NEVER add or override styles in GDScript via `add_theme_*_override()`.
   - All HUD elements, dialogue boxes, menus, cards, and windows must be visually assembled in the Godot Editor. GDScript's only role in UI is binding data and reacting to signals.
2. **The Godot Layer Cake & Signal Architecture**:
   - **Presentation** (HUD/UI/VFX) listens to signals; never mutates game state directly.
   - **Logic** (State machines, Controllers, Systems) orchestrates mechanics.
   - **Data** (`Resource` / `.tres`) is the single serializable source of truth (items, stats, quests).
   - **Infrastructure** (Autoload singletons) coordinates via "Signal Up, Call Down".
3. **Ponytail YAGNI & Anti-Bloat Mandate**:
   - Favor built-in engine nodes and typed GDScript standard functions over custom framework abstractions.
   - Avoid creating classes or components for hypothetical future features.
4. **Scroll & Input Safety**:
   - Controls inside any `ScrollContainer` (e.g. inventory grids, dialogue logs, quest lists) must set `mouse_filter = 1 (Pass)` or `2 (Ignore)` so dragging is not blocked.
5. **Heavy Compute Protocol**:
   - Before executing batch asset processing, dataset simulations, or large multi-file migrations, generate an `implementation_plan.md` artifact with `RequestFeedback: true`.

### Phase 4: General Game Headless Verification Harness

Scaffold a general game CLI and runner under `core/tools/`:

1. **`core/tools/scene_runner.gd`** (`extends SceneTree`):
   - General-purpose offscreen renderer for ANY game scene (main menu, gameplay level, inventory screen, battle arena, character viewer, or dialogue modal).
   - Reads environment variables: `GAME_TARGET_SCENE`, `GAME_OUTPUT_DIR`, `GAME_VIEWPORT_WIDTH`, `GAME_VIEWPORT_HEIGHT`.
   - Instantiates the scene offscreen using `--headless`.
   - Awaits `process_frame` and `RenderingServer.frame_post_draw`.
   - Captures the offscreen buffer using `root.get_texture().get_image()` and writes a clean PNG to `screenshots/debug/`.
   - Dumps `scene_manifest.json` recording all active `Control` and `Node` rects, visibility, and font sizes to catch clipping or offscreen elements automatically.
   - Calls `quit(0)` on success or `quit(1)` on error.

2. **`game.py` (Unified CLI Runner at Project Root)**:
   Python CLI tool providing:
   - `capture --scene <path>`: Renders offscreen screenshots of any `.tscn` scene. Uses an isolated APPDATA profile (`<project>_godot_qa_profile`) so running terminal captures never freezes or conflicts with an open Godot Editor.
   - `test [--suite <name>|--list]`: Discovers and executes headless test scripts under `tests/test_*.gd`, surfacing assertion failures and catching `SCRIPT ERROR` logs.
   - `validate`: Static validator that checks `.tscn` file integrity (detects broken `ExtResource` paths) and audits GDScript for forbidden dynamic UI instantiations (`Control.new()`).
   - `info`: Displays detected Godot executable, engine version, detected game genre, viewport resolutions, and discovered test count.

3. **`tests/test_smoke.gd`** (`extends SceneTree`):
   - Simple smoke test script that verifies the main scene and key game screens can load into memory and advance 2 frames without crashing or throwing script errors.
